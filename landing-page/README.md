# landing-page/ — jumpmade.com

Hand-built static landing page. HTML + Tailwind CSS, served by Caddy on the
existing Hetzner VPS, deployed via rsync.

**Day-10 ship deadline:** 2026-05-01. See `../offer/landing-page-copy.md` for
locked copy and `../decisions/named-mechanism.md` for naming rationale.

## Files

| Path | Role |
|---|---|
| `index.html` | The page. Copy mirrored verbatim from `../offer/landing-page-copy.md`. |
| `styles/input.css` | Tailwind directives + design-system custom properties + component classes. |
| `tailwind.config.js` | Theme: palette, fonts, breakpoints, max-widths. |
| `dist/output.css` | Compiled CSS (gitignored — generated by build). |
| `assets/favicon.svg` | Wordmark mark. |
| `assets/og-image.png` | 1200×630 social share preview. Regenerate with `node scripts/gen-og.mjs`. |
| `scripts/gen-og.mjs` | One-off OG-image generator (uses `@resvg/resvg-js` + system Inter or `fc-match` fallback). |
| `Caddyfile` | Production webserver config. Deploys to `/etc/caddy/Caddyfile`. |
| `deploy.sh` | rsync-based deploy entrypoint. |

## Local dev

```sh
npm install
npm run dev   # tailwindcss watcher → dist/output.css
# open index.html in a browser
```

## Production build

```sh
npm run build
```

Outputs `dist/output.css` minified (~11 KB).

## Deploy

```sh
DEPLOY_USER=root DEPLOY_HOST=1.2.3.4 ./deploy.sh
```

Static-file changes propagate immediately — Caddy doesn't need a reload.

### Server config changes

The `Caddyfile` is **not** rsynced by `deploy.sh` (deploying it would require
sudo on the server). When the Caddyfile changes, manually:

```sh
scp Caddyfile $DEPLOY_USER@$DEPLOY_HOST:/tmp/Caddyfile
ssh $DEPLOY_USER@$DEPLOY_HOST 'sudo mv /tmp/Caddyfile /etc/caddy/Caddyfile && sudo systemctl reload caddy'
```

### First-time server setup

If `:80/:443` is unused on the VPS:

```sh
sudo apt update && sudo apt install -y caddy
sudo mkdir -p /srv/jumpmade.com
sudo chown $USER:$USER /srv/jumpmade.com   # so rsync over SSH can write here
# Copy Caddyfile, reload Caddy (see above).
# Then run ./deploy.sh from your dev machine.
```

If something else is already serving on those ports, do not proceed without
working out the coexistence plan.

### DNS records (TTL 300 for the cutover)

| Host | Type | Target |
|---|---|---|
| `jumpmade.com` | A | Hetzner VPS IP |
| `www.jumpmade.com` | A | Hetzner VPS IP |
| `firstquotesystem.co.uk` | A | Hetzner VPS IP |
| `www.firstquotesystem.co.uk` | A | Hetzner VPS IP |

If DNS is on Cloudflare, set proxy **off** for the first cert issuance (Caddy's
ACME challenge needs direct port 80/443 access). Optionally flip to proxied
afterwards.

## Placeholders

The page intentionally ships with literal `[phone]` placeholders pending the
WhatsApp Business SIM (arriving 2026-04-28). Six occurrences in `index.html`:

- 3 × `wa.me/[phone]` (header, hero CTA, final CTA)
- 2 × `call [phone]` (hero secondary, final CTA secondary)
- 1 × additional URL component overlap (5 lines containing `[phone]` total)

When the number is in hand, do a single find/replace and re-deploy. Append a
note to `build-log.md`.
